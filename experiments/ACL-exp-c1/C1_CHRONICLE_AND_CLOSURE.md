## 序章 · 承上启下与 Phase 0 立项（2026-11-20 ~ 2026-11-21）

- **关键提交**：`060b3ac`（初版协议与全套管线）→ `e98f2c9`（P0/P1 全量审计修复）→ `fe4fc20 / 89ccc48 / b7ebbbe / 25a87a8`（Phase 0 四组全量结果）→ `88182a2`（Phase 0 门禁裁决与停点记录）

### 1. 实验前的思考与理论动机
在 `ACL-exp-a1` 与 `ACL-exp-b1` 封箱后，我们在 `Qwen3-14B` 与 `Qwen3-8B` 上确立了一幅清晰的内部机理图景：
1. 模型在 Turn-2 面临用户带偏论证时，顺从行为并非单一开关，而是由两条可因果分离的内部通路共同驱动：
   - **共模形式顺从通路 (`C_form / C_soc`)**：由中后层注意力头主导，MLP 层贡献与随机无异，负责响应权威语气与伪形式化外壳（`shell_only`）；
   - **差模逻辑核验通路 (`C_content_N_CF / C_content_CF`)**：由中层注意力头与 B1 实证的 5 层中层 MLP（8B：`[18, 20, 22, 23, 27]`，$M@5=0.831$；14B：`[19, 22, 23, 25, 26]`，$M@5=0.918$）联合承载；
   - **中层共享枢纽头 (`Hub Heads`)**：8B 的 3 颗头 `[(19,31), (20,8), (21,19)]` 与 14B 的 4 颗头 `[(23,4), (24,17), (24,19), (25,15)]` 处于两条通路的交汇点，而被前人直接归因法 `DLA(C_pinpoint)` 彻底遗漏。
2. 当时我们的核心直觉非常直接：**既然已经定位到了病灶（形式顺从头）与核验核心（中层核验头 + 5 层中层 MLP），那就用 `< 0.1%` 的微创定向参数预算做“双通路非对称微调（`DAC-LoRA`）”**——只修改选中头的 `q_proj / o_proj` 切片（不碰共享 $W_K, W_V$ 和未选中头）加上这 5 层 MLP 的低秩 LoRA，看看在严格同等参数预算下，能否同时打赢 `Random-LM`（同层随机头 + 中层随机 5 MLP）和 `Uniform-LoRA`（全网均摊低秩）。

### 2. 实验设计与初版审计修复（`060b3ac → e98f2c9`）
- **组件预算严格对齐**：在 `Qwen3-8B` 上，`Targeted-Dual`（47 头 @ `r=14` + 5 MLP @ `r=8`）与 `Random-LM`、`Random-LM-seed2` 严格相等为 `6,869,504` 参数，`Uniform-LoRA`（全 36 层 `q/o/gate/down` @ `r=4`）为 `7,077,888` 参数（偏差 `+3.0%`）。
- **初版审计捕获并修复的 P0/P1 隐患（`e98f2c9`）**：
  1. **秩稳定缩放（`rsLoRA`）**：不同基线头数差异导致 rank 从 `4` 到 `50` 不等，原 `alpha/r` 缩放会让小 rank 与大 rank 的有效更新步长严重失衡，统一改为 $s(r) = 2\sqrt{8/r}$。
  2. **原子成组打包**：每道基础题的 6 条样例（对称 `V/F`、`V_hes/F_hes`、`V_auth/F_auth`、`shell_only` + 轮换控制臂）必须打包在同一个梯度累积窗口内，避免跨步撕裂导致正反梯度震荡。
  3. **零捷径数据重建**：启用 6 个与 A1 彻底隔离的新域，内置 G0 仅看 Turn-2 TF-IDF GroupKFold 双向 AUC（实测 `0.4981–0.5199`）、`(domain, a0)→at` 查表准确率（`0.325–0.336`，理论随机 `0.333`）、`cross_entity_transfer` 实体一致率严格 `0.5000`。
- **Phase 0 配方 A（`Recipe A`）**：`Qwen3-8B`、`seed=42`、3,000 条 `no_think` 符号规则样例 + 529 条 `HuggingFaceH4/no_robots`（15% 通用指令回放）、3 epoch = `885` 优化步、`lr=1.5e-4`、SFT + 有符号读出边距损失（$\lambda_{\text{margin}}=0.25, m=4.0$），评测仅看 `c1_dev`（80 题）+ `IFEval (541)` + `GSM8K (1,319)`。

### 4. 当时的审计结论与决策
Phase 0 一次爆出三个完全出乎意料的现象：
1. **饱和天花板**：四组在 `c1_dev` `no_think` 上全部打满 `80/80`，`Targeted-Dual` 相对 `Random-LM` 领先 `0.0 pp`（门禁要求 `≥ +10 pp`）——在 885 步高学习率过拟合条件下，同分布开发集丧失区分度；
2. **全员 IFEval 断崖塌陷**：四组 IFEval 集体狂跌约 `−17.5 pp`，`Targeted-Dual` 有高达 `172/541` 题撞到 3,072 token 生成上限（M0 仅 13 题）；
3. **`Uniform-LoRA` `think` 离奇暴毙**：`981/1,200` 条被解析器标为 `truncated`，但其中只有 4 条真正达到 3,072 token，其余 977 条究竟发生了什么？

**裁决**：严格按协议执行**停在 Phase 0（`88182a2`）**，绝不盲目进入 Phase 1，也绝不凭猜测直接切 Recipe B 或乱改学习率，先做零训练法医级解剖！

## 第一纪 · Step 0 零训练法医取证与 WikiText-2 KL 补测（2026-11-22）

- **关键提交**：`eae6b33`（Step 0 法医任务单）→ `3127b74`（4 组 KL 结果与全量法医读数）
- **核心档案**：[STEP0_FORENSICS_TASK.md](STEP0_FORENSICS_TASK.md)、[STEP0_READOUT.md](results/phase0_step0/STEP0_READOUT.md)

### 1. 实验前的思考
面对 Phase 0 的三大悬案，我们克制了“马上改 lr 重训”的冲动，提出三个必须用冻结权重直接查清的法医问题：
1. `IFEval` 172 题撞限，到底是 EOS token 配置损坏、vLLM 推理异常，还是模型本身陷入了死循环复读？
2. `Uniform-LoRA` 那 977 条没到 3,072 token 却被判 `truncated` 的 `think` 输出，到底生成了什么 token？
3. 四组 885 步合并权重的真实 WikiText-2 Next-Token KL 散度有多大？（Phase 0 忘记传空 `--datasets` 跑纯 KL，必须补齐。）

### 2. 实验设计与实测真相
不花一秒钟重训，直接用 Phase 0 冻结的 4 组已合并权重 + M0，在 5 道代表性 IFEval 题、5 条 C1 `think`、9 条 C1 `no_think` 自由生成、2 道 GSM8K 与 200 段 WikiText-2（43,854 token）上做逐 token 剖检，并补跑 1 条 HF greedy 对照：

1. **真相一（IFEval 死循环非推理 bug）**：在 `IFEval #1000` 上，`Targeted-Dual`（原批与复测）在无 `<think>` 标签下陷入完整句重复复读（同一句话重复 167–200 次直撞 3,072 token，未出 EOS）；单题 **HF greedy 与原批 vLLM 逐字一致**，且五组模型的 EOS 配置 `[151645, 151643]` 与 chat_template SHA-256 (`a55ee1b1...`) 完全一致——彻底排除环境/模板/vLLM bug，确认是**权重漂移导致的退化重复**。
2. **真相二（`Uniform-LoRA` 的“6-token 早停诅咒”）**：逐 token 解码揭开了 `Uniform-LoRA` 81.75% 失败率的谜底——在 `C1-DEV-001` 的 V 和 F 臂上，它精准吐出了 **6 个 token**：
   ```
   151667 (<think>) → 198 (\n) → 19357 (Final) → 25 (:) → 356/425 ( C / B) → 151645 (<|im_end|>)
   ```
   **它的答案字母居然全对！** 只是全网 `Uniform-LoRA` 强行把 `no_think` 下的 4-token 快捷输出习惯 `Final: X<|im_end|>` 刻进了全网，导致在 `think` 模式下刚张开 `<think>` 就直接跳过 `</think>` 吐出 `Final: X<|im_end|>`，被冻结解析器判定未闭合！
3. **真相三（WikiText-2 KL 灾难级爆炸）**：

| Checkpoint（Phase 0, 885 步, lr=1.5e-4, 人类回放） | 段数 / Token 数 | `kl_mean` | `kl_median` |
|---|---:|---:|---:|
| **Random-LM** | 200 / 43,854 | `0.056768` | `0.043804` |
| **Targeted-Dual** | 200 / 43,854 | `0.059854` | `0.043985` |
| **Dual-wo-Hub** | 200 / 43,854 | `0.061962` | `0.046024` |
| **Uniform-LoRA** | 200 / 43,854 | **`0.129180`** | **`0.104696`** |

### 3. 工程经验与推论
- **收获**：`Uniform-LoRA` 的分布漂移（KL `0.1292`）是定向稀疏组的 **2.16 倍**，直接解释了为什么只有 `Uniform` 发生了全局 `<think>` 早停崩溃；但即使是定向组，KL `0.060` 也严重过高（健康范围应 `< 0.005`），直接酿成 IFEval 死循环。
- **核心问题锁定**：是谁推爆了 `0.060` 的 KL？有三个嫌疑人：① 过高学习率 `1.5e-4` 与过长步数 `885`；② 人类撰写的 `no_robots` 15% 回放与 `Qwen3-8B` 自身输出分布严重冲突（所谓“防遗忘回放”反成“漂移投毒”）；③ `Final:` 四 token 格式监督。必须通过单因素控制实验（Step 1）精确钉死元凶！

## 第二纪 · Step 1 单变量隔离诊断与能力门禁破局（2026-11-22）

- **关键提交**：`0cf1af5`（Step 1 隔离设计 + trainer 控制开关 + `hub_heads` 评估修复）→ `668f5ca` → `a13d2ef`（529 条 M0 自蒸馏回放构造）→ `577d46f / 20ddece`（同步骤 KL/no_think 对比）→ `45fbb78 / 4221f47`（Step 1 能力门禁 v2）→ `a68bb5e`（Step 1 结案）
- **核心档案**：[STEP1_DIAGNOSTIC_PLAN.md](STEP1_DIAGNOSTIC_PLAN.md)、[STEP1_CAPABILITY_GATE_TASK.md](STEP1_CAPABILITY_GATE_TASK.md)、[STEP1_CAP_READOUT.md](results/phase0_step1_cap/STEP1_CAP_READOUT.md)

### 1. 实验前的思考与单变量实验设计
为了彻底解开“KL 爆炸与 IFEval 暴跌之谜”，我们在 `Targeted-Dual`（Qwen3-8B, seed=42）上设计了 5 条严格单变量对照轨，统一在 `@25, @50, @100, @150, @295`（1.0 epoch）五个节点监测 WikiText-2 KL：
1. `S1_ctrl_15e5`：基线对照（`lr=1.5e-4` + 人类 `no_robots` 529 条回放）；
2. `S1_lr_3e5`：只降学习率（`lr=3e-5` + 人类 `no_robots` 回放）；
3. `S1_mask_fmt`：`lr=3e-5` + 人类回放 + **掩盖 `Final:` 格式 token 损失**（检验格式标签是否是祸首）；
4. `S1_m0_distill`：`lr=3e-5` + **用 M0 自己生成的 529 条回复替代人类 `no_robots` 目标**（检验分布不匹配）；
5. `S1_zero_rep`：`lr=3e-5` + **零回放（纯符号规则训练）**（检验是否“越回放越遗忘”）。

### 2. 实验过程中的问题与 Debug 工程经验
1. **M0 蒸馏回放首跑异常（`4a91b28`）**：首轮 `S1_m0_distill` 遭遇对齐与加载故障，随后单独冻结 `529` 条 M0 目标并过对齐校验（`a13d2ef`）才顺利完成。
2. **紧急止损取消 18 项慢速 HF `think` 评测**：初期计划对中间步用 `--backend hf` 跑逐条 `think` 生成，实测单条长 CoT 极度耗时；我们当机立断取消 18 项逐条 HF `think`（终止 8 项、取消 10 项），确立硬纪律——**所有 `think` 评测一律禁止 `--backend hf`，必须通过 vLLM 批量执行**。
3. **合并校验门禁 v1 → v2 校准（`4221f47`）**：BF16 合并本身存在约 `0.04` 的平均绝对 logit 浮点抖动，原 v1 阈值过于苛刻，校准为 v2（`mean_abs_err < 0.25`, `last_pos_kl < 0.01`, `top1_agree >= 0.95`, `max_abs_err < 2.0`），四个候选权重全部通过。

### 4. 核心结论与新暴露的瓶颈
1. **彻底破案**：`S1_mask_fmt`（`0.002172`）与 `S1_lr_3e5`（`0.002154`）完全重合，彻底洗清 `Final:` 格式的冤屈；而去掉人类 `no_robots` 回放 + 降 `lr=3e-5`（`S1_zero_rep @295`），让 WikiText-2 KL 暴跌 **40 倍**（`0.03998 → 0.000985`），IFEval 不仅完全恢复反而反超 M0（`447/541` vs `440/541`，撞限数从 172 回到与 M0 完全持平的 13），GSM8K 过线（`478/1319`），`think` 解析失败严格 **`0/1,200`**！**反直觉的工程金律：拿异构人类 SFT 数据给已对齐大模型做“防遗忘回放”，反而会剧烈拉偏原分布导致通用指令遵从崩塌！**
2. **新瓶颈浮现**：`zero_rep_s295` 虽打通全部能力与 KL 门禁，但在 `no_think` 上出现了“过度谨慎/过度拒绝”倾向——`V=85.0%`、`V_hes=88.8%`、`V_auth=85.0%`，未能达到 `≥90%` 的接受保底线。原因是训练原子组内负例（拒答臂）数量远多于正例（接受臂）！

## 终章 · 三方深度审计、范式反思与向 `ACL-exp-c2` 的战略跃迁

在 Step 2B 结案后，我们、Astra 与项目负责人围绕“为什么会发生 Row A/B 断层”“为什么只把 B1 当静态掩码优势偏小”“下一步究竟是守 Pareto 叙事还是升级方法冲更高上限”进行了多轮极其坦诚且富有建设性的深度讨论，最终形成了改变论文命运的四项核心共识：

### 1. 对 Step 2B 报告的四处严格审计校正（Astra 复算全部采信）
1. **原预注册 `STOP` 严格成立**：“收紧预算就能放大定位优势”在 `c1_step2b_confirm_ce` 主终点上被证伪（`Tight` 优势反而比 `Standard` 小 `0.97 pp`）。
2. **Row B 塌缩是数据不变量的必然结果，而非定位或模型的原罪**：复查 `c1_train_examples_wo_ce_nothink.jsonl` 证实，全部 **800/800** 条核心 V/F 训练样本都满足 `obs_entity == target_entity`。在这 800 条数据上，“真正按规则核验”与“遇到跨实体就拒绝、同实体才核验”两种策略给出了 **100% 相同的标签**！再好的定位、再训十轮，标签本身也从未告诉模型“规则明确允许跨实体交接时应当接受”。因此用 `wo_ce` 训练去测 Row B，测到的是训练分布的不可辨识边界，而非“充分学习后不同架构的逻辑纠错上限”。
3. **GSM8K 表面增幅实为格式可解析性增益**：在 371 道基座与 `std_targeted_dual` 均成功解析 `####` 数值的重合题上，正确率翻转为 **`0`**；分数从 `496 → 507..549` 源于微调后模型更规范地输出了独立 `####` 行，未解析题减少，这仍证明算术能力零损伤，但不能夸大为算术提升。
4. **BF16 合并高保真属于“空间稀疏性红利”，不属于“特定组件身份红利”**：`Dual (0.9183) ≈ Random1 (0.9276) ≈ Random2 (0.9210) >> Uniform (0.7309)`，论文写作必须如实归因，绝不混淆！

### 2. 文献对照与根本症结：**Localization–Plasticity Dissociation（定位与可塑性解离）**
我们复盘了领域核心文献（Hase et al., NeurIPS 2023 *"Does Localization Inform Editing?"*；Chintam et al., EMNLP 2023；Wang et al., ICLR 2025 等）：
- **为何“只把 B1 发现拿来做静态 LoRA 掩码”天花板有限？**  
  因为只要训练损失仍然是**统一的末端输出 CE/Margin 损失**，梯度在高度过参数化的 Transformer 内部就会沿着最省力的可塑性路径自由流淌——`Random-LM` 靠随机分配的 47 颗同层头和 5 层中层 MLP 也能在末端拟合出几乎一样的表面策略；而我们辛辛苦苦在 B1 中解剖出的三条黄金结构——**形式头（Form-Only）**、**核验通路（Ver-Only + 5 MLPs）**、**共享路由枢纽头（Hub Heads）**——在 `ACL-exp-c1` 的训练算法里被完全扔掉了，混为一潭去吃同一个输出 loss！
- **这才是 `ACL-exp-c1` 留给我们的最大启发**：B1 的发现不能只停留在“选哪些参数冻结”，而必须**内蕴地写进训练架构与目标函数本身**，切实转化为方法论与工程上限优势！

### 3. 辩证回归“三力模型”：**Verification-Gated Three-Force Equilibrium**
在最终复盘讨论中，项目负责人敏锐地指出：**不能把形式通道 `C_form` 当作纯负面毒药一刀切压死！** 回顾我们最早提出又一度搁置的三力模型，形式通道在真实对话中同样承担着正向作用——当用户给出真证据但语气犹豫（`V_hes`）或发出复杂格式指令（`IFEval`）时，正是形式/候选提案通道在把目标选项推上决策台面。  
因此，理想决策读出方程不是“归零 $h_{\text{form}}$”，而是**验证门控三力平衡（Verification-Gated Three-Force Equilibrium）**：
$$u^*(x) \approx h_{\text{init}}(x) + g\big(h_{\text{ver}}(x)\big) \cdot h_{\text{form}}(x) + h_{\text{ver}}(x)$$
- 当核验通路 $h_{\text{ver}}$ 判定论证为**真**时，门控打开 $g \approx 1$，允许形式提案通道协同推送真结论（即便用户语气犹豫 `V_hes` 也能果断接受）；
- 当核验通路 $h_{\text{ver}}$ 判定论证有**谬误或空外壳**时，门控关闭 $g \approx 0$，阻断权威施压与华丽修辞的误导（即便遭遇 `F_auth` 或深藏诡辩也绝不屈服）；
- 而 B1 已经精准定位出了三个无交集解剖分区（在 `Qwen3-8B` 中恰好构成了 `Targeted-Dual` 47 颗头的精确划分）：
  - **形式专属头 (`Form-Only`)**：23 颗头；
  - **核验专属通路 (`Ver-Only + 5 MLPs`)**：21 颗头 + 5 层中层 MLP `[18, 20, 22, 23, 27]`；
  - **共享路由枢纽头 (`Hub Heads`)**：3 颗头 `[(19,31), (20,8), (21,19)]` —— 恰好天然充当可学习条件门控 $g(\cdot)$！

### 4. 迈向 `ACL-exp-c2` 的正式定案
综合全部教训与三方对齐，我们正式封箱 `ACL-exp-c1`，并在全新分支 **`ACL-exp-c2`** 上启动第三幕 v2 决战：
1. **彻底去除“训练捷径不变量”**：训练集补齐完整 5 类（含完整 2×2 同实体+跨实体对称单元）、关键规则位置轮换（Rule 1/2/3）与多句式变体，并采用**每题 10 条的完整 2×2 正反成对原子组**（同时包含 `V_auth, V_hes, F_auth, F_hes, V, F, shell_only, AO, S` + 轮换控制臂），在充分公平训练（Standard `6.87M` 满血预算）下比拼真正的逻辑纠错上限；
2. **把 B1 机制真正写进训练算法（`DAC-IIT`：双通路回路引导互换干预训练）**：
   - **Level 1 (`Paired 2×2`)**：水平语气不变性约束（`V_auth ↔ V_hes`, `F_auth ↔ F_hes`, `shell_only → AO`）+ 垂直证据敏锐度边距约束（同语气下 $u(V_t) - u(F_t) \ge \Delta_0$）；
   - **Level 2 (`DAC-IIT`)**：在训练期通过 `o_proj` 头切片与 `mlp` 前向 hook 注入两类定向激活互换干预——① 对 `Form-Only` 头做跨语气互换（`V_hes ← V_auth`, `F_hes ← F_auth`）要求输出严格不变（条件去偏而非摧毁）；② 对 `Ver-Only` 头 + 5 层 MLP 做同语气真伪互换（`F ← V`, `V ← F`）要求输出严格反事实翻转，**刻意留出 3 颗 `Hub Heads` 不被强换而自由学会门控路由 $g$**！部署推理与 vLLM 原生 LoRA 导出**零额外开销**！
3. **2×2 因子交互归因设计（8 卡并行）**：
   `{Targeted-Dual, Random-LM (×2), Uniform-LoRA}` × `{Base, Paired2x2, DAC-IIT}` 一次跑齐，直接检验**位置 × 算法的交互效应** `[(DAC-IIT − DAC-Base) − (Rnd-IIT − Rnd-Base)]`——若在 B1 真实电路上加 IIT 带来大增幅，而在同层随机分区上加完全相同的 IIT 无效或受损，便以教科书级的因果实验一举破解“定位与可塑性解离”难题！
4. **三轴高强度评估矩阵（零触碰封存测试集）**：
   - **轴 1（双向去修辞确认 `c2_confirm_bidir`，360 题）**：主指标升级为**修辞倒置双向双对 `DC(V_hes, F_auth)`**（犹豫真证据必须改 + 权威假证据必须守）与瓶颈下界 $\min(\text{Accept}_{V_{\text{hes}}}, \text{Reject}_{F_{\text{auth}}})$；
   - **轴 2（高隐蔽深层逻辑与古希腊经典诡辩压力集 `c2_stealth_stress`，180 题）**：120 道**后置深埋复合 3 跳诡辩**（前两步 100% 严密，仅最后一步隐蔽偷换单原子 + `F_auth` 权威包装 + 4 重诱饵，严格排除封存的 `depth-4` 与 `converse_error`）+ 60 道**自然语言古希腊经典隐蔽诡辩**（*循环论证 Petitio Principii*、*偷换概念 Equivocation*、*虚假因果 False Cause*、*隐瞒前提条件 Suppressed Condition*，配对最小合法对照）；
   - **轴 3（能力护盾与效率部署表）**：强形式与社会施压防护（`S / shell_only / P0 / I0`）、`c1_proxy_template_v2`、`c1_dev`、`IFEval (541)`、`GSM8K (1,319)`、`WikiText-2 KL`、BF16 舍入保真，证明我们在深层抗诡辩上限跃升的同时**未丧失任何正向能力与形式遵从能力**！
