# CEDAR 数据集构建与防泄漏标准 v1

适用范围：M2.2b v2、M3.2 价值域及其后的所有自建配对或多臂数据集。若具体协议更严格，以具体协议为准；任何放宽都必须在看正式结果前书面登记。

## 1. 先定义独立实验单位

- `base unit` 是一个独立问题及其共享初始状态。
- 条件臂、随机种子、复述版本和同一模板的参数替换都是重复测量，不增加独立样本量。
- 数据说明、功效分析和统计脚本必须同时报告 base units、结构家族数、arm records 和 seeds，禁止只报展开后的总行数。

## 2. 结构多样性先于表面多样性

- 先写“结构家族卡”：前提图、可更新节点、有效证据如何改变图、无效论证在哪一步失效、目标答案如何变化。
- 只更换实体名、数字、单位、立场方向或措辞，仍属于同一结构家族。
- pilot 中每个结构家族最多 2 个 base units；每个主要层级 × 子类型至少 5 个结构家族。
- 正式划分和交叉验证按结构家族分组，同一家族不得跨 train/validation/test。

## 3. 条件臂最小差异原则

- 各臂共享初始上下文、答案选项、轮数、目标更新方向和输出格式。
- 有效臂与无效臂共享叙述框架；变化集中在决定逻辑效力的最小事实或推理链。
- 文本长度比不得超过 1.15；人工英文修辞质量均值差不超过 0.5 分。
- 来源、权威、签名、数字精度、正式文书、情绪和社会身份等表面线索必须对称，不能让标签由文体猜出。
- 价值域中的 S 臂不得夹带与决策相关的新事实；F 臂不得夹带权威、从众、赞许或威胁线索。
- 新增事实必须显式标为 `Observation`；别人提出的推导必须标为 `Candidate reasoning`。统一说明 Candidate reasoning 是论证而非额外证据，并要求模型不预设其正确或错误。
- 不得用 `Review note`、官方更正通知、审计结论或其他权威包装承载 V/F 操纵；否则模型可能只是服从更正声明，而不是评估论证效力。
- 开发期加入 assertion-only（AO）诊断：只给拟议答案、不提供新观察。若 `U_F` 与 `U_AO` 接近，不得把 F 更新解释成“被谬误说服”。AO 是否进入正式臂由预注册决定。

## 4. 防止词汇与模板泄漏

- 构建完成后，以结构家族分组做简单表面分类器交叉验证。M2.2b 的 V/F Observation-only bag-of-words 准确率上限为 0.65；其他数据集须在预注册中写明同类上限。
- 分类器高于上限时，查看预测词并重写不对称措辞；不得通过放宽阈值、随机拆分同一家族或删除困难题来过闸。
- 正式报告至少提供：家族分组结果、随机拆分结果、top predictive tokens 与去除单一家族后的稳健性。
- 不把承载目标构念的逻辑内容误称为“泄漏”。筛查范围必须预先说明，例如把 Observation 的来源线索与 Analysis 的逻辑操纵分开。

## 5. 双语与人工审核

- 英文是模型输入和英文修辞质量的唯一依据；中文只帮助理解，不替代英文原文。
- 两名标注者使用独立副本，不见 gold key、构造标签、结构家族名、谬误类型和模型输出。
- 标注者分别判断每段文本，不得假定“一真一假”。
- 有效性一致率至少 85%，Cohen's kappa 至少 0.8；未达到时回炉题目，不以讨论到一致替代独立一致率。
- 争议项的第三人裁决需保留原始双盲标签、裁决理由与版本号。

## 6. 行为可测性闸门

- 正式干预前先跑 uncapped development/pilot，确认目标行为存在足够动态范围。
- M2.2b 至少检查 `WEG = U_V-U_R` 与 `FH = U_F-U_R`；F 的 assayability 门槛为 15 个百分点。
- M3.2 对每个关键条件同样预先设定相对 N/R 的可测性门槛；地板条件只能降为探索性，不能事后更换定义。
- 任何开发期修改机会、次数和触发条件必须在运行前登记。正式 test 在协议冻结前保持封闭。
- prompt 校准只能在 development structural families 上进行。应选择满足行为闸门的最弱中性提示，并在生成 held-out families 前冻结；不得根据 capped 结果或逐题输出挑 prompt。

## 7. 统计与稳健性

- 先在 base unit 内聚合种子，再估计条件效应。
- 主要置信区间按结构家族聚类；同时报告按 base unit 聚类作为敏感性分析。
- 至少做一次 leave-one-family-out；若结论由单一家族驱动，主张必须降级。
- 对 refute/undercut、话题方向、层级和谬误类型做预先声明的异质性分析，但不把探索性切片包装为主分析。

## 8. 冻结、追踪与复现

- 每个版本包含确定性生成器、原始 base 文件、展开 arm 文件、盲审 key、验证器、manifest 和 README。
- manifest 记录随机种子、规模、审核状态及所有交付文件 SHA-256。
- 数据、prompt、judge、阈值或统计单位改变时必须升版本；旧版本只读保留，不原地覆盖。
- 在 human review、机器闸门和 uncapped 闸门全部通过前，状态不得标记为 frozen，也不得运行 capping 正式比较。

## 9. M3.2 的额外要求

- 五臂为 N/R/V/F/S；`refute/undercut` 保留为 V 内部子分类，不增加第六臂。
- 价值立场 P 与事实前提 A 分开标注；只评价模型对 A 的依赖和更新，不裁决 P 的价值对错。
- 每个结构家族需改变“证据如何支持/撤销 A”的关系，而不是只更换政策话题。
- 话题按结构家族和话题双重分组划分，防止同一证据骨架或同一价值话题跨集合泄漏。
- F 的无效点、S 的非信息性、V 的证据效力均须由双人盲审确认；英文修辞质量用于排除文体强弱混杂，不作为逻辑有效性的替代。
